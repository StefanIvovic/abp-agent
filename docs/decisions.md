# Decision log

| # | Decision | Why |
|---|---|---|
| D1 | New repo; reuse proven parts of the earlier prototype, reviewing each on the way in | Fresh structure without repeating solved problems. The earlier prototype stays as it is |
| D2 | Keep the stack: LangGraph, LlamaIndex, Postgres, Neo4j, MLflow, Prefect, FastAPI, Streamlit, MCP. DSPy only if a phase needs it | Proven in the earlier prototype. Query rewriting never passed its gate there, so it isn't carried over |
| D3 | One agent, ABP only | One domain removes the multi-corpus and two-agent plumbing |
| D4 | Claude grades answers in a session, calibrated against hand-checked labels; the grader stays swappable | Strata and the 27B can't share the GPU. Trade-off: graded evals can't run unattended, and Claude isn't independent on keys it wrote |
| D5 | Own Compose project and host ports (API 8011, UI 8502, MLflow 5001, Prefect 4201, Neo4j 7475/7688, Postgres 5435, Ollama 11436) | Runs beside the earlier prototype |
| D6 | Eval keys carry quotes checked by code against a pinned ABP commit (`d1bf7f6f2b`) | Wrong keys cost hours in the earlier prototype (q001, q030, q041). A key can no longer rest on memory |
| D7 | Forum questions are drawn by seeded random sample, with written selection rules | Hand-picking favours easy questions. See `evals/README.md` |
| D8 | The test split is sealed by hash after human review | The earlier prototype changed test keys after seeing results. A change now has to be deliberate and visible |
| D9 | Eval cases can carry chat history | The repeated-answer bug needed history, so single-turn cases couldn't catch it |
| D10 | Agent model is qwen3.8-27b; the router uses JSON schema output | Measured before writing the agent. See `docs/model-trial.md`: JSON schema 75 of 75, forced tool call 70 of 75 |
| D12 | Search docs and code separately, then alternate the results (`search_both`) | In one ranking docs win, because they share the question's plain English: c014's proof ranked 3rd in code alone and 31st mixed. Dev, 4 code cases, proof in the top 10: docs only 0, mixed 0, balanced 1, balanced with model-written search words 2 |
| D13 | Parse C# with tree-sitter; chunk by type, then whole members; index split-up names | Text splitters cut code anywhere. BM25 keeps `AbpIdentityUserValidator` as one word, so "user validator" would miss it |
| D14 | Stop tuning retrieval at 12 dev cases | Overall proof in the top 10 is 0.58 with model-written words, on one search. That's too few cases to tune on, and the agent can search again. Revisit with a reranker if agent evals point here |
| D15 | The graph is parsed from code, with no LLM: modules, inheritance, options, and docs pages naming a type | The code states these facts exactly. 17 closed lists scored F1 1.00, and search found 0.61 of the same names in its top 10. Every type links to a chunk, so facts can be cited |
| D16 | Types are matched by simple name | The code doesn't always say which namespace a base comes from. Known limit: 253 names are shared by 599 types, and those share their edges, so a list for such a name can include the wrong type's relations |
| D11 | Don't rely on the model to pick code over docs | Both 27B models searched the docs first on all 4 code-only cases. Phase 3 and 5 must make code reachable anyway, for example one search over both sources |
| D17 | Ollama runs on the CPU | On the GPU, its few hundred MB pushed the 27B over the 24 GB card: prompt reading fell from about 1,100 to 48 tokens a second, and research answers took 100 seconds or more. Embedding one question on the CPU is cheap. Trade-off: loading all the data is slower |
| D18 | Research answers aren't streamed; only chit-chat and off-topic are | The output guard can replace a research answer, so a user must not see the draft. Progress events still show the searches |
| D19 | The agent eval's automatic checks prove behaviour, not correctness | Dev x3: pass^3 0.88 after fixing a scorer that missed "does not ship", proof reached 0.92, median 18.7 s. Both remaining failures are citations the output guard removed. Whether explanations are right is read separately against each key |
| D20 | The agent is told it can't see commercial module code | On a real bug it reached the right conclusion from the wrong code and wrote "the source code confirms it". The ABP team placed the bug in the commercial change password page, which isn't in our data |
| D21 | Report automatic and read scores separately | After D20, dev x3: all 54 runs passed the automatic checks, pass^3 1.00, median 20.7 s. Reading found what they miss: c001 run 3 named the wrong mechanism and missed the validator, yet passed |
| D22 | Live answers get a code-name check, and unknown names are shown as unverified | Measured first on saved answers: all 7 known invented names caught, 11 of 390 names flagged. Plain code, so almost free. Names are flagged, not removed, because some are real .NET types outside ABP |
| D23 | The LLM claim check is a review aid in evals, not a live check | On 92 saved answers it flagged 59, many wrongly, for about 4 more seconds each. It did find real problems, including 3 in the original sign-in answer, so it lists suspects for a reader |
| D24 | Turns without sources get fixed text, and no turn but research reaches the model. This replaces D18's streaming of chit-chat and off-topic | On test-v1 a real question with an attack in it went to off-topic, where the model wrote invented permission code with no search and no guard. The router now keeps mixed messages on research, and a wrong route can only refuse, not invent |
| D25 | Read scores use the user's rules: a clear no first when ABP lacks the thing, one false detail fails the answer, a name the answer itself warns about doesn't | test-v1: automatic 45/45, read at most 31/45 and 7/15 questions. dev-v4: read 55/72 and 14/24. The automatic checks now enforce the clear no and per-case patterns, but can't find a false detail |
| D26 | Calls in code samples must appear in what was retrieved this turn, or the reader is told to check them | Bad samples were the top failure. Checking calls against all of ABP found one real problem in 193 samples, and syntax checks flagged harmless snippets. Checking against the passages of the turn flagged every known bad sample. It can only warn: a seen call can still be used wrongly |
| D27 | Text the model writes beside a tool call is not sent back to it | All 4 false "I need to correct my earlier answer" lines had such a draft, and 67 of 275 research turns had one. It is written from memory before any result, and the user never sees it. Stored messages keep it |
| D28 | The first call has a 1,000-token limit and one retry if it skips the tool | LM Studio does not enforce a required tool call. On dev-v5 two c028 runs wrote invented citation numbers until the length limit, about 90 seconds, then got the not-found reply |
| D29 | Monitoring stays in MLflow, and collecting failures is automatic but promoting them is not | MLflow already has the views, so there is no custom dashboard. Each turn is one trace with decision tags, ratings live on the trace, and evals.candidates collects thumbs down and guard actions. A person writes the key, because a key has to be proved against the source |
| D30 | A citation is valid if the model was given that passage on this turn or an earlier one it can still see | Monitoring found the guard removing real sources on follow-ups. New case c042 runs the earlier question for real and failed 5 of 6 before the fix. `asked_before` was added because `history` is only text, so it could never reproduce this. A passage older than the history window still counts as invented |
| D31 | MCP exposes the read tools behind one shared bearer token, and fails closed | The earlier prototype had no login. A token in `.env` suits a few trusted clients on one machine. A public server needs OAuth 2.1, which means replacing only `TokenCheck`. Only `/mcp` is protected, so the rest of the API stays on localhost |
| D32 | CI runs lint and unit tests in the app image; evals stay local | Same image as local runs, so no second setup. The tests need no services, checked with no network and no `.env`. `evals.verify` needs the ABP repository, and agent evals need a 27B model |
| D33 | The repository stays local, and CI is kept ready but not connected | The user decided CI is not needed for now. The workflow stays in the repository, and its steps pass locally. It has never run on GitHub |
| D34 | A large type's chunks show its declaration above the members; search text stays as it was | Reading test2 failures showed that 774 of 5,947 types had no chunk showing their bases or attributes, so the model couldn't see what a class inherits. The header already held the line for search, so the search text and embeddings did not change. Rewriting the rows still moved results a little |
| D35 | `analyze_query` runs before the router: code reads exact names, the model picks technology, platform and intent from fixed lists, and the result reaches the agent as a hint for the turn | The user's design, after answers came back in C# for a JavaScript question. Code keeps the names exact and marks abp.* as JavaScript, because the model called abp.ajax in a Razor Page razor. A schema keeps the model to classifying. A failure costs only the hint and is recorded. Trade-off: one more model call on every turn, including greetings. The prompt rules were written with c049 in view, so test2 can't show whether they work |
